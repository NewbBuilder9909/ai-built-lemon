# Parallel agent work: protocol and current allocation

**26 September 2026; allocation and delivery rules updated 27 September.** Replaces [phase-2-parallel-work-scope-2026-09-25.md](archive/phase-2-parallel-work-scope-2026-09-25.md), which described Phase 2 as in progress and has since been overtaken.

More than one coding agent (Claude and Codex so far) works on this repository. This page says how to do that without collisions, and who owns what now. Keep the allocation table current; it is the one place to look.

## What went wrong on 25–26 September

Codex was briefed to assess Phase 2 and avoid colliding with Claude. Its assessment said "keep changes in separate new artifacts rather than editing Claude's implementation". It then built tenant onboarding in the **same checkout**, while Claude was building repository links. Nothing was lost, and the two streams separate cleanly by path, but four collisions happened or nearly happened:

| Collision | Effect | Rule it motivates |
|---|---|---|
| Both agents edited `docs/tenancy.md`, `CLAUDE.md`-adjacent docs and `README.md` | Edits interleaved in one uncommitted file; either agent could have reverted the other's | Shared docs have one owner at a time (rule 4) |
| Codex regenerated `staffops-routes.txt` | The snapshot now mixes both streams' routes; a commit of either stream alone would fail the route test | Only the integrating agent regenerates snapshots (rule 5) |
| A full-suite run caught Codex mid-edit | Two spurious architecture failures, investigated as if real | Work in your own worktree (rule 1) |
| Both agents' integration tests used `UmbracoBase_IntegrationTests` | Concurrent runs share rows and migration state | Own test database (rule 2) |

## Rules

1. **One worktree per agent, one branch per stream.** `git worktree add ../ProgrammePulse-<stream> -b <branch>`. Never build or edit in another agent's checkout. The main checkout belongs to whoever is integrating.
2. **Own test database and build output.** Set `PP_TEST_SQL_CONNECTION` to `Database=UmbracoBase_<stream>` and use `--artifacts-path artifacts/<stream>`. The default database is shared by everything that doesn't set this. Drop it when the stream's PR merges (rule 13).
3. **Read-only first.** An assessment, review or plan edits no application file. If it produces a document, it's a new file under `docs/`, named for the stream.
4. **Shared files have one owner at a time.** These are `CLAUDE.md`, `README.md`, `docs/tenancy.md`, `docs/architecture-review-2026-09-24.md`, the composers, the migration plans and `TestScenarios/Northstar/capability-routes.json`. Others propose changes in their own doc, and the owner applies them.
5. **Generated contracts are regenerated only on integration.** `staffops-routes.txt` (`PP_UPDATE_ROUTE_CONTRACT=1`) is regenerated by the agent merging a stream, after reviewing the diff, never by a stream mid-build.
6. **Migration steps are allocated before they are written.** Each plan's next step number is reserved in the table below. Two streams taking the same number breaks upgrade order.
7. **Commit by path, never `git add -A` in a shared tree.** Before committing, list `git status` and confirm every path is yours. Never chain a destructive git command after one that can fail (see the 19 September incident in agent memory).
8. **Hand over with evidence.** Finish with build, test and view-check output, and a list of files touched, so the integrator can verify without re-deriving.

## Delivery: how work reaches `main`

On 27 September four streams had to be integrated by hand:

- three days of laptop work sat on `modernize/dotnet-20260923` with no pull request;
- the laptop pushed its Aikido security fixes to a branch with no PR;
- a Claude session pushed the HWB-name rename with no PR, and it went on to conflict with `main` in 68 files;
- #19 was built against a `main` that moved underneath it, and had to be rebuilt as #22.

Nothing was lost, but only because someone went looking. These rules close that gap:

9. **`main` is the only long-lived branch, and it moves only through a pull request with green CI.** No direct pushes, including from the laptop.
10. **Every stream ends in a pull request.** An agent session that commits pushes its branch and opens a PR before it stops, or says in its hand-over why it didn't. A branch with no PR is invisible, and invisible work is how the backlog above built up.
11. **A merged branch is finished.** Follow-up work starts a new branch from the latest `main`; never add commits to a branch whose PR has merged.
12. **Keep branches current and short.** Merge `main` into a branch that is more than a day behind, and split work that would run past a few days. A conflict found early is a merge; found late, it is a rebuild.
13. **Clean-up is routine, not an event.** GitHub deletes merged PR branches automatically. Run `./scripts/prune-remote-branches.ps1` (a dry run unless you pass `-Apply`) for the rest: it deletes branches already in `main`, archives and deletes branches whose changes `main` already has (a squash merge, a cherry-pick), and archives any other branch you name. Archiving pushes an `archive/<branch>` tag before the branch is deleted, so no commit is lost. Test databases go the same way: `./scripts/prune-test-databases.ps1` (also a dry run unless `-Apply`) drops LocalDB databases named like ours, keeping `UmbracoBase`, `UmbracoBase_Demo`, `UmbracoBase_IntegrationTests`, whatever `PP_TEST_SQL_CONNECTION` and `PP_DEMO_SQL_CONNECTION` name, and anything passed in `-Keep`. Pass an unmerged stream's database in `-Keep`.
14. **Build before you push, wherever you are.** Cloud sessions get the .NET SDK and PowerShell from `.claude/hooks/session-start.sh`, so the fast unit tests and `./scripts/check-views.ps1` run there too. CI stays the gate, not the compiler. SQL-backed integration tests need Docker and remain CI-only in the cloud.
