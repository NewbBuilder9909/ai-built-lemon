## Rescan of `main`, evening of 27 September

The rescan after #23 and #24 still listed 17 findings. Some are new, some
were only partly fixed by #23, and some are re-detections of code that was
already fixed or is safe. Aikido's code-analysis findings name files but
not the offending lines, so where a finding says "+N others" and nothing
more was found, the status says so. Fixes are on
`claude/vibrant-thompson-ik6qfm`.

| Severity | Finding | Where | Status |
|---|---|---|---|
| High | SQL injection via string concatenation | `ProgrammeRepository`, `SecurityAssuranceRepository` +1 | **Not exploitable; hardened.** Every value is a parameter. The interpolated text is table and column names taken from DTO constants, never from input. `SqlIdentifier.Quote` (from `cd836e6` on `main`) now refuses anything but a plain identifier and bracket-quotes it at every place that interpolates one: `SqlMultiRow` insert and update, the batched and single tenant checks in the Programme Ops and Contract Ops repositories, and the external-id upsert. Aikido's autofix (#27) also left an inline check in `SqlMultiRow.InsertAsync`. **Mark as false positive in Aikido** with that reason. |
| High | Path traversal | `ContractDocumentStorageService` | **Fixed.** Uploads were already safe (GUID file name, allow-listed extension). Downloads opened `StoragePath` exactly as stored, and a URL built an unauthenticated client for whatever host it named. A download now rebuilds the location from the document's own keys, under the configured root, share or container. A stored path naming anything else returns 404. |
| High | Cross-tenant isolation bypass | `StaffAuditLogRepository` | **Fixed.** #16 fixed the audit page. The GDPR export's `GetForEntityAsync` still read by entity id alone, which was exempted as an "owned key". It now takes `tenantId`, and the exemption is removed. |
| High | Excessive authentication attempts | `MfaVerificationService` | **Fixed (second pass).** #23 checked the lock first and counted the failure afterwards, so parallel requests all passed the check. Waiting out the 15-minute lock also restored a fresh budget of 10 (960 guesses a day). Each attempt is now counted under a row lock before it is checked. Locks double from 15 minutes to 24 hours, and the 100th consecutive failure locks MFA until an Admin resets it. Proven against SQL Server with 40 parallel guesses (`docs/mfa-security-runbook.md`). |
| Medium | Improper access control | `ExecutiveDataService`, `ReportingQueryService` +3 | **No further defect found in the two named.** `ExecutiveDataService` requires ManageStaff (plus ManagePlatform for a tenant purge) and takes the tenant from the actor. The reporting team scope was fixed in #23. Its controller now also declares the gate (next row). The other three files are not identified in the report. |
| Medium | Authorization bypass in controller | 26 controllers | **False positive, with one hardening.** Gates are declarative filters, enforced at build time by `ControllerGateTests` and over HTTP by the persona harness. `StaffExecutiveDataController` was gated only inside its service and now declares `[RequireCapability(ManageStaff)]`. Still gated only in their services: `StaffExecutiveReviewController` and `StaffExecutiveDecisionController` (capabilities differ per action), and `StaffAccountController` (runs before sign-in). **Mark as false positive in Aikido.** |
| Medium | Secret in a SQL Server connection string | `ci.yml` | **False positive.** The password is generated with `openssl rand` on each run and masked in the logs. The container listens only on 127.0.0.1 and is deleted afterwards. The rule matches the text `Password=`. **Mark as false positive in Aikido.** |
| Medium | Incomplete data deletion | `EngineeringEvidenceRepository`, `SuggestionRepository` +4 | **Fixed in #23; no further gap found.** Needs the report's line-level detail to go further. |
| Medium | Business logic bypass | `StaffIdentityResolver` | **Fixed (decision taken 27 Sep: follow the recommendation).** An email match no longer attributes anyone. The person stays unresolved and the matching profile becomes the queue row's suggestion (ProgrammeOps step 27), approved in one click at `/staffops/programme/identities`. Approval re-checks that the profile is still active in the tenant and still has that email, and audits `ApprovedEmailMatch`. On upgrade, people who were matched only by email appear on the queue at their next sync and are unattributed until approved. |
| Medium | Business logic bypass | `StaffServiceController` | **Fixed in #23.** |
| Medium | Improper input validation | `CsvWriter` | **No defect found.** Every CSV export goes through `CsvWriter`, whose formula guard covers `=`, `+`, `-`, `@`, tab, carriage return and leading spaces. The template and sample CSVs are built from code constants. **Mark as resolved.** |
| Medium | MFA bypass | `MfaRecoveryCodeGenerator` | **Fixed (second pass).** #23 still accepted the legacy unsalted SHA-256 hashes, so every code issued before then stayed brute-forceable from a copied database until it was used. Only salted PBKDF2 now verifies. Anyone who holds only old codes signs in with their authenticator app, or is reset and re-enrolled. |
| Medium | Uncontrolled resource consumption | `ProgrammeRepository`, `StaffEvidenceConnectionController` +3 | **Fixed (second pass).** The GitHub, Azure DevOps, Freshdesk and Aikido sync buttons had no rate limit, unlike Programme sync and file import. They now use the `sync` policy, and `SyncRateLimitTests` fails the build if a `/sync` action lacks it. The Reporting Hub, Cost Summary, trend capture and Service Health accepted any date range: `?from=0001-01-01` read all time history and walked every day since year one for each person. `ReportingPeriod` now caps a range at 731 days. |
| Medium | Generic API key | `scripts/accessibility/audit.mjs` | **Fixed.** A hardcoded TOTP seed, the RFC documentation example, that no persona has used since #23. The audit now reads `PROGRAMMEPULSE_PERSONA_TOTP_SECRET`, which the persona seeder also honours. |
| Low | Insufficient verification of data authenticity | `GitHubEvidenceClient` | **Fixed (decision taken 27 Sep: follow the recommendation).** The client reads GitHub's `verification.verified` for each commit. A commit row counts as verified authorship only when the signature is verified and the author is the signer. Co-author trailers, unsigned commits, commits ingested before this change and Azure DevOps commits are labelled "authorship not verified" wherever the evidence is shown (SkillsEvidence step 06, evidence schema version 2). Pull requests and reviews are authenticated actions and unaffected. |
| Low | Account or identity enumeration | `StaffOnboardingService` | **Accepted residual.** The message has been neutral since #23. But member emails are unique across tenants, so any refusal tells the Admin submitting the form that the address is taken. Only a signed-in tenant Admin can reach the form. |
| Low | Insecure cookie configuration | `LanguageController` | **Fixed in #23.** The cookie is `HttpOnly`, `Secure` and `SameSite=Lax`, and holds only a culture name. **Mark as resolved.** |
| Low | Generic API key | `MfaStorageIntegrationTests` | **Fixed in #23.** The seed is generated per run and no literal remains. **Mark as resolved.** |
